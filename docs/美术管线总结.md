## 0. 一句话总纲

**双管线（程序化 artgen + AI gen_asset）+ 数据驱动注册表 + 固定路径契约 + 截屏诊断链**——零外包零付费，两天的产出：200+ 资产、7 场景全覆盖、5 层内容素材、100 张参数化装备图标。

## 1. 双管线分工（什么图用什么做）

| 管线 | 工具 | 适合 | 不适合 |
| --- | --- | --- | --- |
| **程序化** artgen.py | Python + Pillow，数据驱动注册表 | 几何感强的：棋子/图标/纹章/UI 符号/效果图标/层卡卡面——风格 100% 统一、秒出、可参数化（尺寸/配色/品级框） | 有生命感的怪物/场景 |
| **AI** gen_asset.py | 本机 ComfyUI（SD1.5 + 像素 LoRA）→ HTTP API → Pillow 后处理 | 怪物头像/场景背景/有叙事感的立绘 | 精确复用同一形象（变体会漂移）、批量 UI 图标（风格失控） |

**判断口诀**：几何可描述 → 程序化；要"生命感/叙事感" → AI；节点图标等批量 → 程序化效果图标 × 参数化配色。

## 2. AI 管线要点

### 2.1 本地部署（4GB 显存档）
- ComfyUI 便携版 + `--lowvram`；SD1.5 底模（DreamShaper 8）+ 像素 LoRA（PixelArtRedmond）
- 启动 bat：**纯 ASCII** + `CD /D %~dp0` + `SET PIP_INDEX_URL=清华镜像`（Manager 依赖安装用）
- 下载：模型走 hf-mirror（20MB/s）；GitHub 大资产直连会死；curl 必须 `--ssl-no-revoke`

### 2.2 生成 → 后处理 → 落盘
```
提示词（形状硬锚） → API 排队 → 512 出图 → LANCZOS 降到目标尺寸
→ 调色板量化（锁风格） → 四角取色 flood-fill 抠底 → 落盘
```

### 2.3 提示词方法论（最重要的经验）
1. **形状硬锚防人形漂移**：日系怪物名（旋風雀/叶隐蛙）会被画成兽耳娘。描述必须写**形状**——"round sparrow body / frog legs / grass ball / totem pole"，绝不写名字意译。两轮实测：形状锚一轮达标，意译词两轮全灭。
2. **负面词全家桶**：`human, hair, cat ears, kimono, dress, clothes, humanoid body, humanoid face` + 常规（blurry/realistic/text/watermark…）。
3. **风格三锁**：统一风格前缀（所有怪共用）+ 固定 seed（变体用同 seed 微调 desc）+ 调色板量化。
4. **质量门自动化**：抠底透明率 < 20% 自动换 seed 重出（工程会话的占位方块教训：美术产物必须过质检门，不过关不入库）。
5. **普通/关键分治**：普通节点用程序化效果图标（按数据键分类 ×10），只有关键/传奇/Boss 才 AI 单独生图。

## 3. 程序化管线要点

- **数据驱动注册表**：`ELEMENTS / EQUIP_SLOTS / EQUIP_RARITIES / EMBLEM_*` 都是表——加新内容 = 表里加一行，重跑一条命令全量再生。
- **参数化抑制组合爆炸**：装备图标 = 25 槽位形状 × 4 品级框 = 100 张，绝不逐件手绘/生图。
- **固定尺寸特例**：对齐运行时尺寸的 tile（如棋盘 84px）用独立常量，不跟全局 --size。

## 4. 工程接入契约（零改动接入的秘诀）

1. **固定路径命名先行**：工程按约定路径 load（`monsters/<slug>.png` / `equipment/{slot}_{rarity}.png`），美术照路径产出——接入 = 文件落盘，零代码。
2. **slug 命名以工程侧预留映射为准**：映射不一致时**改自己的文件名**，不改工程代码。
3. **代码构建 UI 的场景**（market/kennel/paragon/character/offline）：改视觉**必须改代码**——只改 tscn 会被运行时重建覆盖（踩过两次）。
4. **新 PNG 必跑** `godot --headless --path <项目> --import`——否则 `ResourceLoader.exists` 静默失败（最大隐形坑）。
5. **美术产物必须过质检门再入库**：抠底透明率/物种一致性人工抽查；不过关的宁可回滚（V2-4 变体全灭已验证）。

## 5. 多会话并行纪律

- **热文件不碰**：其他会话有未提交改动的文件列入手断清单，完工后再接入。
- **提交前 diff 审查**：逐文件确认改了谁的什么，外人成品可"顺带代提交"但须单独成笔注明。
- **slug/路径冲突**：以工程侧已提交的映射为准，美术改资产名对齐。
- **后台 job 输出落盘**（PS 管道缓冲会吞输出）；推送失败重试循环（GitHub 502/重置是常态）。
