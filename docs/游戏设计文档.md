> 本文档是游戏的唯一设计事实源：记录已拍板的设计决策、当前数值与待定问题。
> 分工：内容/数值/玩法/设定由用户拍板，助手负责整理成文并实现。

## 1. 一句话概念

在世界树的世界里，人们向树献上吉尔（G）换取等级（祝福），等级达标便能登上更高一层——挂机赚钱、献金升级、逐层登树。

## 2. 世界观与设定（用户提供）

- **主题**：日式奇幻。
- **舞台**：一棵世界树。世界以"层"划分，玩家从第一层（树根）出发。
- **核心规则**：人们通过花钱提升自己的等级；只有等级达标，才被允许从第一层进入第二层。
- **升级的设定包装**【已拍板 2026-10-09】：向世界树**献金**，换取更深的祝福（即升级）。
- **舞台命名（助手拟，可改）**：第一层 = "树根之街"。

## 3. 核心循环

```
挂机收入(吉尔/秒) ──> 累积吉尔 ──> 向世界树献金升级
      ▲                                │
      └──── 等级提升 → 收入提高 ────────┘
                                       └──> 等级达标 → 解锁下一层（世界观钩子）
```

- 挂机时玩家的主视觉是"吉尔数字在涨"；主动操作是"献金升级"。
- 消消乐（= 在世界树冒险战斗打怪）是第二条收入来源，M2 加入。

## 4. 经济系统：三种收入来源

| # | 来源 | 形态 | 状态 |
| --- | --- | --- | --- |
| 1 | 挂机收入 | 按时间自动增长 | **M1 实现** |
| 2 | 消消乐（冒险战斗） | 玩消消乐赚钱，等级越高步数越多 | M2 |
| 3 | 附加玩法（如炒股） | 小游戏提供额外收入 | M3+ |

## 5. 成长系统

- **MVP 单线**【已拍板 2026-10-09】：等级即收入——升级既提高挂机收入，又推进登层门槛。
- **多线成长**：后续扩展方向（收入线 / 战斗线 / 商业线并行），架构上预留。

## 7. M1 数值基准【待用户确认/调整】

> 结构已拍板，以下绝对数值是助手的初始基准，改数值只动 `data/balance.gd` 一个文件。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 初始吉尔 | 0 G | |
| 基础收入 | 1 G/秒 | Lv.1 时 |
| 每级收入增幅 | +2 G/秒 | 线性：收入 = 1 + 2×(等级-1) |
| 首次献金（升 Lv.2） | 10 G | 费用 = 10 × 1.15^(等级-1) |
| 自动保存间隔 | 10 秒 | 另有关窗即存 |

按此基准，从 Lv.1 献金到 Lv.10 总计约 168 G，纯挂机约 2~4 分钟可达——MVP 演示节奏偏快，方便验证，正式节奏由你定数值。

## 9. 待定问题（M2 开工前问答确认）

1. **消消乐形态**：经典三消（swap）？点消（同色连点）？还是别的？
2. **步数机制**："等级越高步数越多"的等级指玩家等级还是消消乐自身的等级？
3. **战斗包装**：每一步如何映射为攻击？敌人血量/波次怎么呈现？
4. **结算**：消消乐收益是固定赏金还是与消除表现挂钩？
5. **炒股**：玩法范围与界面（K线？简单涨跌按钮？）。
6. **美术**：日式奇幻的参考作品/像素or立绘方向。

## 10. 技术架构摘要（助手负责）

- Godot 4.7 / GL Compatibility / PC 横版 1920×1080（canvas_items 拉伸）。
- 自动加载单例：`EventBus`（信号总线）→ `GameState`（数据唯一持有）→ `Economy`（收入引擎）→ `SaveManager`（存档）。
- 数值全部集中在 `data/balance.gd`（数据驱动，改数值不改逻辑）。
- 存档：`user://save.json`，schema v1（version/money/level/floor/total_earned），10 秒自动保存 + 关窗即存。
- M1 的 UI 由代码构建（`scenes/main/main.gd`），美术阶段再迁移到场景文件。
- 冒烟测试：`tests/balance_test.gd`（无头跑数值公式断言）。
